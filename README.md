# 5주차 과제 - OAuth 2.0과 소셜 로그인

Spring Boot로 **자체 회원가입과 로그인**, **구글 소셜 로그인**을 구현합니다. 두 로그인에서 발급받은 서비스 Access Token으로 내 정보를 조회하고, 구글 로그인으로 받은 토큰으로 2주차에 구현한 API도 호출해 봅니다.

---

## 과제 요구사항

### 1. 자체 회원가입과 로그인 (필수)

1. 이메일과 비밀번호를 받아 회원을 등록합니다. 이미 가입한 이메일은 중복 가입을 막습니다.
2. 비밀번호는 `PasswordEncoder`로 해시해 저장합니다.
3. 이메일과 비밀번호를 확인하고, 성공하면 서비스 Access Token과 Refresh Token을 발급합니다. 비밀번호가 틀리면 `401 Unauthorized`를 반환합니다.

### 2. 구글 소셜 로그인 (필수)

1. 처음 로그인하면 회원으로 등록하고, 같은 구글 계정으로 다시 로그인하면 **같은 회원**으로 처리합니다.
2. 로그인에 성공하면 자체 로그인과 동일하게 **서비스 Access Token과 Refresh Token**을 발급합니다.
3. 같은 이메일의 자체 가입 계정이 있고 구글 계정이 연결되어 있지 않으면 `409 Conflict`를 반환합니다. 로그인 취소와 인가 코드 누락은 `ErrorResponse` 형식으로 처리합니다.

### 3. 로그인 결과 확인 (필수)

1. 자체 로그인과 구글 로그인에서 각각 받은 **서비스 Access Token**을 Postman의 Bearer Token에 넣고 `GET /users/me`를 호출합니다.
2. 응답에서 로그인한 회원의 ID와 이메일을 확인합니다. Access Token 없이 요청하거나 Refresh Token을 넣으면 `401 Unauthorized`가 반환되어야 합니다.
3. OAuth Client Secret, JWT 서명 키, DB 비밀번호는 환경변수로 관리합니다. 커밋과 제출 이미지에서 실제 비밀값, 인가 코드, 토큰은 가려 주세요. 기본적인 Java 컨벤션을 지킵니다.

### 4. 2주차 API 연결 (필수)

1. 2주차 과제에서 본인이 구현한 API 하나를 가져옵니다. 예를 들어 `GET /students`처럼 기존 목록 조회 API를 사용할 수 있습니다.
2. 가져온 API는 로그인한 회원만 호출할 수 있게 합니다. 구글 로그인에서 발급받은 **서비스 Access Token**으로 호출했을 때 정상 응답이 오는지 확인합니다.

### 5. 추가 구현 (선택)

- **이메일 인증**을 추가합니다. 자체 회원가입 시 만료 시간이 있는 일회용 인증 링크를 메일로 보냅니다. 인증을 마친 회원만 이메일과 비밀번호로 로그인할 수 있게 하고, 만료되거나 이미 사용한 링크로는 인증할 수 없도록 처리합니다.
- **계정 연동**을 추가합니다. 자체 가입한 회원이 로그인한 상태에서 구글 계정 인증을 완료하면, 연동을 시작한 회원의 기존 계정에 구글 사용자 ID를 저장합니다. 연동한 뒤 비밀번호와 구글로 각각 로그인해 같은 회원 ID가 나오는지 확인합니다. 이미 다른 회원에게 연결된 구글 계정은 연동 요청을 거절합니다.

## Postman 확인 항목

브라우저에서 강의 자료의 **구글 인가 요청 URL**을 열어 로그인합니다. 콜백에서 받은 **서비스 Access Token**을 Postman의 **Authorization → Bearer Token**에 넣고 테스트합니다.

### 필수

| 상황 | 응답 |
| --- | --- |
| 새 이메일로 `POST /auth/signup` | `201 Created` |
| 이미 가입한 이메일로 `POST /auth/signup` | `409 Conflict`, 상황에 맞는 오류 코드 |
| 올바른 이메일과 비밀번호로 `POST /auth/login` | `200 OK`, 서비스 Access Token과 Refresh Token 발급 |
| 잘못된 비밀번호로 `POST /auth/login` | `401 Unauthorized`, 상황에 맞는 오류 코드 |
| 자체 로그인으로 받은 Access Token으로 `GET /users/me` | `200 OK`, 자체 가입한 회원의 ID와 이메일 |
| 구글 로그인으로 받은 서비스 Access Token으로 `GET /users/me` | `200 OK`, 구글로 로그인한 회원의 ID와 이메일 |
| Access Token 없이 또는 Refresh Token으로 `GET /users/me` | `401 Unauthorized` |
| 구글 로그인으로 받은 서비스 Access Token으로 2주차 API 호출 | API에 맞는 정상 응답 |
| 토큰 없이 같은 2주차 API 호출 | `401 Unauthorized` |

### 선택

| 상황 | 예상 응답 |
| --- | --- |
| 이메일 인증 전 `POST /auth/login` | 로그인 거절, 서비스 토큰 미발급 |
| 이메일 인증을 마친 뒤 `POST /auth/login` | `200 OK`, 서비스 Access Token과 Refresh Token 발급 |
| 구글 계정 연동 후 비밀번호와 구글로 각각 로그인하고 `GET /users/me` 호출 | 두 요청 모두 `200 OK`, 같은 회원 ID |

이메일 인증을 구현했다면 브라우저에서 만료되거나 이미 사용한 링크가 거절되는지 확인합니다. 계정 연동을 구현했다면 다른 회원에게 이미 연결된 구글 계정으로 연동을 시도했을 때 요청이 거절되고 기존 연결이 유지되는지 확인합니다.
